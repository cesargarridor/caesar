Requisitos

  • Windows: 64 bits. Caesar usa WebView2 del sistema; si falta, el instalador se encarga de ello.
  • macOS: Intel o Apple Silicon (el .dmg es universal).
  • Linux: x86_64 con WebKitGTK 4.1 (por ejemplo Ubuntu 22.04 o posterior). El .deb declara sus dependencias; el AppImage las lleva casi todas, pero necesita una distro reciente. Los paquetes se compilan en Ubuntu 22.04.
  • No necesitas cuenta: el modo invitado funciona sin ella.

Pasos de instalación

Windows

  1. Descarga el .exe (o el .msi).
  2. Ejecútalo y sigue el asistente.
  3. Abre Caesar desde el menú Inicio.

macOS

  1. Descarga el .dmg y ábrelo.
  2. Arrastra Caesar a la carpeta Aplicaciones.
  3. Ábrelo desde Aplicaciones o Launchpad.

Linux

sudo apt install ./Caesar_x.y.z_amd64.deb

o, con el AppImage:

chmod +x Caesar_x.y.z_amd64.AppImage
./Caesar_x.y.z_amd64.AppImage

Ubuntu y otras distros

Linux no muestra advertencias de reputación, pero hay un par de mensajes que pueden sorprender. Con el .deb, apt puede mostrar una nota inofensiva si el archivo está en tu carpeta personal; con el AppImage hay que darle permiso de ejecución.

Terminal — ubuntu
user@ubuntu:~$ sudo apt install ./Caesar_x.y.z_amd64.deb
Reading package lists... Done
...
N: Download is performed unsandboxed as root as file '/home/user/Caesar_x.y.z_amd64.deb' couldn't be accessed by user '_apt'. - pkgAcquire::Run (13: Permission denied)

Con el AppImage: chmod +x Caesar_*.AppImage y ábrelo. Si tu distro no lo abre, instala libfuse2.

¿Por qué sale esto? Es lo normal

Caesar es un proyecto nuevo y de código abierto: es completamente nuevo y todavía no tiene historial de descargas.

SmartScreen y sistemas parecidos se fijan en la reputación del archivo y en si lleva firma de código de pago. Un programa recién publicado no tiene ninguna de las dos cosas, y el aviso sale con cualquier software nuevo.

El aviso no significa que sea peligroso: significa que el sistema aún no lo conoce. Puedes comprobarlo tú: todo el código es público y puedes verificar el archivo con su huella SHA-256 (más abajo).

Cómo verificar la integridad

En la página de cada Release, GitHub muestra junto a cada archivo de la sección Assets su huella SHA-256. Calcula la del archivo que descargaste y comprueba que coincide:

# Windows (PowerShell)
Get-FileHash .\Caesar_x.y.z_x64-setup.exe -Algorithm SHA256
# macOS
shasum -a 256 Caesar_x.y.z_universal.dmg
# Linux
sha256sum Caesar_x.y.z_amd64.AppImage

Si no coincide, no lo instales y vuelve a descargarlo. Esta comprobación detecta descargas corruptas o alteradas, pero no sustituye a la firma de código (ver más abajo). Las actualizaciones automáticas, además, están firmadas con minisign y la app verifica la firma antes de instalarlas.

Actualizaciones automáticas

  • Por defecto, al abrir la app busca una versión nueva en github.com/cesargarridor/caesar/releases; si la hay, la descarga, la instala y se reinicia sola. Tus pestañas y borradores se conservan.
  • Cada paquete de actualización va firmado con minisign y la app comprueba la firma antes de instalarlo.
  • Para desactivarlas: Ajustes → Actualizaciones. Desde ahí también puedes pulsar Buscar actualizaciones cuando quieras.
  • En Linux, la actualización automática solo funciona con el AppImage; el .deb hay que reinstalarlo a mano.
  • Al comprobar actualizaciones, GitHub recibe tu IP y una petición estándar; más detalle en la política de privacidad.
