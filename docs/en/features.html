Caesar guide: every feature, one by one

Caesar is a desktop API client built to be fast: it starts instantly, keeps everything on your machine and does not ask for an account to get started. This guide walks through every feature with a GIF of the real result, from your first request to tests, GraphQL, WebSockets and teamwork.

What is Caesar?

Caesar is a desktop API client for Windows, macOS and Linux. It lets you build, send and test HTTP requests, GraphQL and WebSocket, organize them into collections and share them with your team, all from a clean interface where color and the keyboard save you clicks.

  • Local-first: in Guest mode your collections live on your device. It works offline and without an account.
  • Truly fast: it is built with Rust and Tauri, not a bundled browser.
  • Familiar: if you come from Postman or Insomnia, you can import your collections and your pm.* scripts keep working.
  • Fair Source (FSL): the code is public and free to use. It is not open source: selling it is prohibited.

Who is it for? For anyone who tests APIs every day (backend, frontend, QA, mobile) and wants a lightweight, private, frictionless tool. Also for anyone who needs to share collections with their team without setting up infrastructure.

Why it is so fast

Caesar's speed is not a trick: it comes from how it is built.

Rust instead of a bundled browserRequests are executed by a Rust core and the window uses the web engine that already ships with your system. The result: instant startup and low memory use.
Your data is right next to youCollections, variables and tabs are read from your disk, without waiting for any server. Opening Caesar does not depend on your connection.
Nothing to load on startupNo mandatory sign-in screen, no telemetry and no analytics running in the background.
Fewer clicks, more keyboardEvery command has a shortcut and you can change it. Paste a cURL and the request is already built.

The first time, a system warning may appear, especially on Windows (SmartScreen). That is normal for a new project, and the warnings guide explains what to click. After that, Caesar updates itself.

No command line. Caesar is a desktop application: you do not need Node, Docker or any extra installation to use it.

Your first request

Open Caesar and click New tab (Ctrl+T). Choose the method (GET, POST, PUT, PATCH, DELETE, HEAD or OPTIONS), type the URL and click Send or press Ctrl+Enter.

  1. Type the URL in the top bar.
  2. Click Send. You will see an animation of the request steps (resolving the name, connecting, sending, receiving).
  3. Read the response below: status, time, size and body.
  4. Press Ctrl+S to save it to a collection.

Besides the seven usual methods, in Settings you can add extra methods (for example the WebDAV ones). Only CONNECT and TRACE are rejected.

Parameters and headers

The Params and Headers tabs use a key/value editor: you add rows, turn them on or off with the checkbox without deleting them, and the URL updates by itself.

  • Uncheck a row to test without it and without losing it.
  • You can use {{variables}} in keys and values (see Variables and profiles).
  • If you paste a URL with ?a=1&b=2, the parameters appear in their table.

Request body

In the Body tab you choose the format your API needs:

TypeWhen to use it
JSONModern REST APIs. Editor with syntax checking and colors.
TextXML, plain text or other raw content.
Form-dataForms with file attachments (up to 100 MB per file).
x-www-form-urlencodedClassic forms.
GraphQLDedicated Query and Variables editor (see GraphQL).

For safety, Caesar only attaches files that you have chosen in the system file picker.

Reading the response

The response is shown with the status (color-coded), the time and the size, and three views:

  • Pretty: formatted, colored JSON. You can hide empty values to read it better.
  • Raw: the text exactly as it arrived.
  • Timeline: the request steps with their duration.

With the JSONPath filter you keep only the part you care about, for example $.data[0].id. And with Ctrl+F you search inside the response (see Tabs and search).

Responses are read up to 10 MB; if one is larger, Caesar truncates it and warns you so the window does not freeze.

Paste and copy cURL

If someone hands you a curl command (from an API's documentation, from the browser's developer tools or from a colleague), paste it straight into the URL bar. Caesar creates the request with its method, headers and body.

And the other way around: copy any request as cURL to share it in a ticket or run it in a terminal. There is a command for it (no default shortcut, you can assign one).

Authentication

In the Authorization tab you choose how to identify yourself. Caesar supports these types:

No authInheritBearerBasicAPI KeyDigestNTLMOAuth 1.0OAuth 2.0WSSEAWS Signature v4Akamai EdgeGrid

The Inherit option is the most convenient: you define authentication once on the collection or folder and every request inside uses it. If the token changes, you change it in one place.

Tip: store the token in a variable ({{token}}) and use that variable in the authentication; that way you do not paste it into every request.

Variables and profiles

Variables let you write {{baseUrl}} instead of a fixed URL. There are three levels:

  • Global variables: valid in all your collections.
  • Collection variables: only for that collection or folder.
  • Variable profiles: named sets (Development, Staging, Production...) that you activate with the selector next to Send. It is the equivalent of Postman's Environments.
  • {{x}} variables are shown in a different color in the URL, headers, parameters and authentication, so none slips by.
  • Ctrl+click on a variable opens its value to view and edit it without leaving the request.
  • Ctrl+Space opens the variable picker.
  • You can mark variables as secret so they are not visible at a glance.
  • When you import from Postman, its environments become profiles and its globals become global variables.

Tests and scripts

The Scripts tab runs a script when the response arrives (its results show up in a tab of the response panel). It uses a Postman-style syntax (pm.*), so what you already know works:

pm.test("responds 200", () => {
  pm.expect(pm.response.code).to.equal(200);
});

const data = pm.response.json();
pm.test("returns users", () => {
  pm.expect(data.length).to.be.above(0);
});
  • pm.test and pm.expect to check status, headers and body.
  • pm.response.json() to read the body already parsed.
  • pm.environment.set, pm.collectionVariables.set and pm.globals.set to store values.

Safe by design. Scripts run in a dedicated interpreter for a subset of JavaScript: no network, no file system access and no eval. That is why an imported script cannot do anything outside its own scope.

Chaining requests

A typical case: sign in and use the token in the other requests. With a test on the login request:

const r = pm.response.json();
pm.environment.set("token", r.access_token);

From then on, any request can use {{token}} in its header or in Bearer authentication. You run the login once and the rest is authenticated, with no copy and paste.

Collections and folders

Collections are the notebook where you keep your requests. Create one from the sidebar, add folders inside folders and drag and drop to reorder.

  • Each collection or folder can have its own variables and authorization, inherited by whatever it contains.
  • It saves itself: Caesar autosaves and keeps your tabs and drafts when you close it.
  • You can share a collection with your team (see Sync and teams).

Code generator

With the </> button you turn the active request into code ready to paste into your project. There are 20 languages and libraries, including cURL, Python (Requests), JavaScript (Fetch, XHR), Node.js (Axios), Go, Rust, Java, Kotlin, C#, PHP, Ruby, PowerShell, Swift and Dart.

You can adjust options such as indentation, timeout or following redirects, and copy the result with one click.

GraphQL

Choose the GraphQL body and Caesar gives you one Query editor and another for Variables, just like in Postman:

  • Load the schema through introspection.
  • Autocomplete for fields and types as you type.
  • Schema explorer to browse types and fields.
  • Beautify to format the query.
  • Generate variables from the query and an operation selector when there are several.

GraphQL requests are imported and exported with Postman.

WebSockets

Create a WebSocket request, connect and watch the conversation in a timeline: what you send and what you receive, with time and size.

  • Write the URL with ws:// or wss:// (if you use http(s), it is converted).
  • You can set subprotocols separated by commas.
  • Send text or binary messages (in hexadecimal or base64) and inspect binaries in a hex dump.
  • Supports {{variables}} in the URL.

Tabs and search

Work with as many tabs as you need. Caesar remembers the ones you had open and restores them exactly as they were when you start it again.

  • Ctrl+T new, Ctrl+W close, Ctrl+1…9 go to tab N.
  • Alt+← / → goes back to the tab you visited before or after.
  • Ctrl+F searches in the response or in the editor.
  • Right-click or Ctrl+Shift+W closes them all and takes you to the home screen with the cat.

On macOS, Ctrl is replaced by Cmd.

Workspaces

A workspace is a separate set of collections, variables and tabs: one for work, another for personal projects, another per client. You switch from the sidebar selector.

Guest mode and accounts without Pro include one workspace; with Pro you can have as many as you like.

Themes, fonts and languages

Caesar ships with six themes: Monokai (default), Dracula, Tokyo Night, Nord, One Dark and GitHub Light for those who prefer a light background.

You can also choose the font and text size, turn off animations and adjust the sidebar width. The interface is available in Spanish, English, German, French and Italian.

Sync and teams

With a Pro account you can use the same collections on several computers and share them with other people.

  • Personal sync: your collections, variables and profiles show up on all your devices. Changes are merged per item, so two devices do not overwrite each other's work.
  • Encrypted on your device: what is uploaded is encrypted from your computer; the service only stores unreadable data.
  • Recovery key: you keep it, and it lets you recover your data if you lose a device.
  • Linking a new device: it is approved from another of your devices with a six-digit code that you compare on both screens.
  • Teams: share a collection or a workspace with a code; whoever enters it joins and sees the changes.

Important: in a shared collection, anyone with the code can read and modify its contents; there are no roles. Share the code only with people who should be able to edit.

Privacy and security

  • No telemetry or analytics. Caesar does not send usage data.
  • The interface makes no network requests: they are run by the Rust core, which validates URLs, only allows http and https and limits the size of responses and files.
  • Your keys never leave the system: the encryption key is stored in your operating system's keychain.
  • Minimal permissions and a strict security policy in the application.
  • In Guest mode your data never leaves your device.

More in Security and privacy and in the privacy policy.

Updates

Caesar updates itself: on startup it looks for a new version and, if there is one, downloads it, installs it and restarts. Your tabs and drafts are kept. Every package is signed and the application verifies the signature before installing it.

  • In Settings → Updates you can turn them off or click Check for updates.
  • On Linux, if you install Caesar from the Snap Store (sudo snap install caesar or the Ubuntu App Center), Snap updates it automatically; with the AppImage it updates inside the app, and the .deb is reinstalled manually.

Best practices

  1. Use variables for whatever changes (server, version, tokens) and profiles for each environment.
  2. Define authentication on the collection and leave requests on "Inherit".
  3. Add at least one test to every important request: status and a body check.
  4. Name requests with a verb and a resource ("List users", "Create order") and group them in folders.
  5. Export a copy of your important collections from time to time.
  6. Do not leave secrets in the URL: use secret variables or authentication.
  7. Use one workspace per project or client so variables do not get mixed up.

Troubleshooting

The request does not connect

Check that the URL starts with http:// or https://, that there is no unresolved variable (it shows in a different color) and that you have a connection. Look at the response timeline: it tells you which step fails.

SSL certificate error

If you are testing a local server with a self-signed certificate, turn off Verify SSL in Settings. Turn it back on for real APIs.

I get 401 or 403

Check the Authorization tab: if it is on "Inherit", check the collection's. Confirm the token has not expired and that the variable exists in the active profile.

The request times out

Raise the timeout in Settings. With 0 the maximum (1 hour) is used, meant for debugging.

My tests do nothing

Tests run after the response is received, so you need to send the request. If there is an error in the script, it is shown next to the results.

I cannot sync or share

These features require Pro. In Guest mode or with the account on trial, Caesar works locally. If you have already paid, click I have already paid, check in Account and subscription.

Frequently asked questions

Is Caesar good for testing APIs?

Yes: it covers REST, GraphQL and WebSocket with tests, variables, profiles, Postman import and code generation, in a lightweight app that works offline.

Is it free and open source?

It is free in Guest mode and its code is public, but it is not open source: it uses the FSL license and selling it is prohibited. Each version becomes MIT after two years.

Where are my collections stored?

On your device. They only leave it if you turn on sync or share with a team, and in that case they are encrypted.

Can I bring my Postman collections?

Yes. Import the collection file (and the environments, which become profiles) from the sidebar.

Do my Postman scripts work?

Tests with pm.test, pm.expect, pm.response.json() and the functions to store variables do. Caesar uses a safe interpreter for a subset of JavaScript, so a script that depends on external libraries or the network will not run.

Is there a command line or CI integration?

For now Caesar is a desktop application. You can export requests as cURL or code to use in your scripts.

Do I need an account?

No. An account is only needed to sync and work as a team.

Which systems does it run on?

Windows (.exe and .msi; coming soon to the Microsoft Store), macOS (Intel and Apple Silicon) and Linux (Ubuntu App Center / Snap Store with sudo snap install caesar, .deb and AppImage).

Try it now

It is free to download and you do not need an account. If something is missing or you find a bug, tell us on GitHub.
